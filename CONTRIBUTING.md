# Contributing

Contributions are welcome. This repository is meant to make the idea-before-building phase clearer, more reusable, and easier to hand off to coding agents.

Useful contribution types:

- better interview questions
- more generic examples
- improved handoff templates
- real-world workflow feedback
- bug fixes / clarity fixes

## Guidelines

- Do not contribute private product plans.
- Examples should be generic and reusable.
- Keep skills modular.
- Keep the product/spec workflow separate from the build execution workflow.
- Preserve the split between idea capture, design doc, implementation spec, handoff, and review.
- Keep `idea-workflow` focused on creating build-ready source material, not on doing the coding work itself.

## Before Submitting

Please check:

- Markdown renders cleanly.
- Skill frontmatter remains valid.
- Skill names and paths are consistent.
- Templates still match the workflow described in the README.
- The change does not introduce private or customer-specific details.

If possible, run the workflow on at least one sample idea before submitting changes.

## Pull Request Notes

When opening a pull request, include:

- what changed
- why it changed
- how you validated the Markdown/frontmatter
- whether you tested the workflow on a sample idea
- any open questions or follow-up work
